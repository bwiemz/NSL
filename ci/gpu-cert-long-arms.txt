# GPU certification lane — per-target timeout overrides
# ======================================================
#
# `scripts/gpu-cert.sh --run` gives every cargo invocation the same budget:
# NSL_CERT_TIMEOUT, default 900s. That default is right for the ~350 gates
# that launch a handful of kernels and exit. It is wrong for the handful that
# train a real model end to end, and when it is wrong the gate is reported
# TIMEOUT — indistinguishable, in the report, from a kernel that hung.
#
# A gate listed here gets `max(NSL_CERT_TIMEOUT, <seconds>)` instead. MAX, not
# override: `NSL_CERT_TIMEOUT=3600 ./scripts/gpu-cert.sh --run` for a debugging
# sweep must never be silently shortened back down by this file.
#
# The budget is PER CARGO INVOCATION, and gpu-cert.sh makes up to two per
# target: one batched run of all the target's gates, then — only if that run
# goes red — one run per gate in its own process. Both get the same budget, on
# the reasoning that a gate slow enough to need it is slow in either mode.
#
# WHY A SEPARATE FILE and not a fifth column in ci/gpu-cert-manifest.tsv:
# `--write-manifest` dumps `inventory()` verbatim and `gpu-gate-inventory.awk`
# emits exactly four fields, while `--check-inventory` is a byte-exact diff. A
# fifth column would go permanently red and then be erased by the next
# regeneration. Keying on the source path instead means column 1 here is
# checkable against column 1 there, which is what `--check-long-arms` does.
#
# Format (tab-separated):
#   <source file><TAB><seconds>
#
# Seconds must be > 900 (below that the default already applies and the entry
# is noise) and <= 7200. `scripts/gpu-cert.sh --check-long-arms` enforces the
# format, the range, and that every path is a real manifest row in a class the
# lane actually runs — so a test-file rename turns into a failure here instead
# of silently reverting the gate to 900s.

# ── Full-training gates ─────────────────────────────────────────────────
# Each of these drives at least one complete training run to convergence
# through a nested `nsl run`/`cargo run` subprocess, so the wall clock is a
# training job's, not a kernel launch's.

# Three trainings of the 10.1M model (128 + 128 + 32 micro-batches) in one
# test, each a separate `cargo run --features cuda` subprocess.
crates/nsl-cli/tests/pretrain_loss_decrease_gpu_e2e.rs	1800

# Three 48-step runs compared for allocator drift; the file's own header
# budgets ~5 minutes, which leaves no headroom on a cold target.
crates/nsl-cli/tests/long_run_drift_gpu_gate.rs	1800

# Eleven gates in one batch, each spawning ~2 nested `nsl run` compilations
# of the CSLA layerwise fixture. The batch, not any single gate, is what
# exceeds the default.
crates/nsl-cli/tests/csla_layerwise_gate.rs	1800
