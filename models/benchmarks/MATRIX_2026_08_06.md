# Item 6 — the standardized throughput matrix (2026-08-06)

RTX PRO 4500 Blackwell 32 GB, driver stack per `project_cachyos_linux_env_setup`.
Harness: `matrix_bench.py` — arms interleaved round-robin (3 rounds, best
round reported; the PR #454 lesson), timing pass uninstrumented, attribution
pass separate with its times discarded. `on_step` fires per MICRO-batch, so a
"step" is `batch × seq` tokens for every arm, accumulating or not.

## Why this run replaces the 2026-08-02 one

The first run **silently lost three arms**: the generated program hard-coded
`grad_clip=1.0` (refused by `--layerwise-accum`) and omitted the
`grad_accumulation ≥ 2` FASE-Deferred requires, so the 500M `srbf16` and both
1B `layerwise` arms failed to *build* — and the harness dropped them from the
results with no trace. Its attribution was also fictional: compile-time
markers were grepped out of the runtime stderr (every admission read false),
and the region regex lacked `re.M` (empty tables). All fixed; build-refused
arms are now recorded as entries.

## What the table establishes

- **1B@2048 trains on this card only under the layerwise stack** (CSLA
  window-buffered accumulation + weight streaming). Reference and the
  optimized bundle both OOM at microbatch 1; layerwise runs at 902 ms/step,
  2,271 tok/s, 17.7% MFU — the highest MFU in the whole matrix, because the
  larger matmuls amortize launch overhead.
- **At 1B@512 the layerwise stack is also FASTER** than the optimized bundle
  (349 vs 446 ms/step, +28% tokens/s) at essentially equal peak memory in
  this configuration — the win is the FASE-Deferred window schedule, not
  memory alone (note `grad_accumulation=2` halves optimizer steps per token).
- **50M optimized is 8–14% faster than reference across microbatches** and
  runs at microbatch 16 where reference OOMs. Divergence vs reference stays
  ≤ 1e-4 max-rel (the fused LM head's known numerics).
- **500M matmul-dtype ladder**: fp32 405 → bf16 321 → srbf16 239 ms/step.
  The srbf16 arm's edge over plain bf16 is the residency schedule + fused
  SR-AdamW step (fewer optimizer steps per token at accum=2, layerwise
  windows), not the GEMM mode — it runs the TF32 default GEMM.
- The 50M scaling curve says the small model is launch-bound: MFU climbs
  7% → 14% with microbatch and flattens past mb8; the region attribution
  shows memcpy (the DataLoader H2D + loss D2H path) at 70–82% of attributed
  host time at large microbatch.

## Attribution notes (pass B, times discarded)

- Admissions are now real: the optimized arms report `fused_lm_head=True,
  csha_plan=True, wggo_plan=True, fuse_peephole=1, sdpa_fused_forward=True`;
  the layerwise arm (built on `--source-ad`, since the bundle's WGGO
  per-param FASE table is refused by `--layerwise-accum`) reports them false,
  as expected.
- PCIe is the LAST profile interval (steady state): ~0 MiB/step H2D for
  every resident arm; the 1B layerwise arms stream ~3.7 GiB/step H2D —
  weight streaming's cost, and the reason it fits.
- HBM traffic is not collected (no runtime counter; `--ncu` exists for
  `dram__bytes` when needed).
